# Performance and load testing (gate E-04)

Owning module: tooling. Method and rationale: ADR-0030.

| File                         | What it is                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------- |
| `targets.json`               | profiles (dataset, users, duration), operation mix, p95/error/throughput targets |
| `LAST_RUN_smoke.md`          | generated by the last `pnpm test:load` (CI-sized, enforced)                      |
| `LAST_RUN_representative.md` | generated by `pnpm test:load -- --profile representative` (enforced)             |
| `LAST_RUN_stress.md`         | generated by `pnpm test:load -- --profile stress` (60 users, report only)        |

## Run it

```bash
pnpm test:load                                     # smoke, ~30 s
pnpm test:load -- --profile representative         # ~5 min (2.5 min seeding 100 000 positions)
pnpm test:load -- --profile stress                 # ~4 min, never fails on targets
```

Windows PowerShell: the same commands. Each run uses a fresh disposable database and drops it.

## Agreeing the targets (product owner)

1. Check the dataset sizes and concurrency in `targets.json` against the real warehouse(s): SKUs,
   bins/locations, stock positions, concurrent operators and tablets, documents per day.
2. Adjust the p95 targets if the operators need faster answers.
3. Set `"status": "AGREED"`, `"agreedBy": "<name, role>"`, `"agreedAt": "<date>"`.
4. Re-run the representative profile on production-equivalent hardware (staging) and record the
   result in `docs/WMS_RELEASE_EVIDENCE.md`. Only then can gate E-04 pass.
